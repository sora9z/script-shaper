## 3. 현재 `_PATTERN_SYSTEM_PROMPT`가 커버하지 못하는 것

현재 프롬프트의 가정: "화자줄 = 이름 토큰 + 공백/괄호 구분자 + 대사", 한국어 시나리오.

| # | 갭 | 근거 작품 | 결과 |
|---|---|---|---|
| G1 | 구분자 없이 붙는 화자(`은수(N)대사`) 표현 불가 | 은수좋은날 | 패턴 학습 실패 → 항상 폴백 |
| G2 | "화자줄이 없는 문서"를 말할 방법이 없음 | 감시자들, 미녀는괴로워 | 모델이 억지 regex 생성 위험 (예: SRT 순번 `^\d+`이 매치율 33%로 검증 통과 가능) |
| G3 | 씬헤더-인명 충돌 경고 없음 | 은수좋은날 | 화자줄 regex가 씬헤더를 물어 경계 오판 |
| G4 | 이름 문자 집합이 좁음 | 은수(콤마·언더스코어·숫자), 후아유(`/`) | 예시·regex 불완전 |
| G5 | 노이즈 라인(타임코드·순번·컷번호·파일명)을 예시로 뽑지 말라는 지시 없음 | 감시자들, 미녀는괴로워, 은수 | 오염된 few-shot |
| G6 | 주석 태그 목록이 `(E)(N)(O.L)(F)` 중 일부만 언급 | 은수좋은날 | 태그 처리 불일치 |

## 4. 부산물 발견 (이번 프롬프트 개선 범위 밖 — 별도 이슈 후보)

1. **`.xls` 지원이 현재 깨져 있음**: `xlrd` 미설치라 `read_file`이 `.xls`에서 크래시. 또한 실제 `.xls` 대본은 슛리스트 표라 "셀=대사" 가정 자체가 성립 안 함 → 컬럼 기반 파서(대사 컬럼 식별 + 화자 forward-fill + 비대사 행 필터)가 별도로 필요.
2. **baseline 콜론 regex(`^[^:\n]+:\s*`)의 과잉 매치 실증**: SRT 타임코드 라인 1,179개(100%)가 "화자명: 대사"로 오인돼 추출 결과의 70%를 차지. 끝 앵커가 없는 것이 근본 원인. (청킹 경계용으론 무해하나, 화자 제거용으로는 재검토 여지)
3. **영문 자막에서 규칙 추출 전멸**: 한국어 어미 휴리스틱이 영어에 무의미 — 실제 대사의 32%만 생존. `<i>` 태그 제거 로직도 부재.
4. **hwp 리더 부재**: `pyhwp`(hwp5txt)로 추출 자체는 가능함을 확인 — 리더 추가는 별도 과제.

## 5. 확정된 설계 결정 (사용자, 2026-07-02)

1. **지문(내레이션) regex 식별은 포기** — 지문/대사 구분은 분류기(AI)의 몫. 패턴 분석은 **화자줄 regex에만 집중**.
2. **학습된 문서별 regex는 기존 `SPEAKER_DIALOGUE_REGEX_LIST`에 동적 union** → `[콜론형, 3+공백형, 문서학습형]` 결합 세트.
3. **청킹 경계 판정은 결합 세트 사용** (`chunk_by_speaker_boundaries`). 경계 오탐=이른 절단, 미탐=50줄 폴백이라 비용 낮음 → 넓은 baseline 섞어도 안전.
4. **검증(매치율 5~60%)은 학습 regex 단독** — baseline(특히 과잉 콜론 regex)을 검증에 섞으면 학습 실패가 가려짐.

## 6. 열린 결정 → 확정 (2026-07-02)

- **화자줄 없는 문서(G2) 감지 시 동작: (b) 전면 폴백로 확정.** 사용자 판단: "최종 목표는 대사 추출 — 화자명이 없으면 (패턴 기능이) 굳이 필요 없다." 모델이 빈 regex를 반환하면 `validate_pattern`이 거부 → 고정 50줄 + 일반 프롬프트. 배선 변경 없음.

## 7. 개선될 `_PATTERN_SYSTEM_PROMPT`에 반영할 요구사항 정리

1. 화자줄 regex **하나만** 요구 (지문/씬헤더 regex 요구 제거 — 씬헤더는 오탐 방지용 참고로만).
2. regex는 구분자 3형(콜론/3+공백/**붙음**)을 모두 표현할 수 있어야 하며, 붙음형 예시 제공.
3. 화자 없는 문서면 그렇다고 답하게 (빈 regex + 문서 유형 설명). 순번·타임코드·컷번호는 화자줄이 아님을 명시.
4. 씬헤더가 인명으로 시작할 수 있음(`은수 집, 주방 (D)`)을 경고 — 학습 regex가 씬헤더에 매치되면 안 됨.
5. 이름 문자 집합 확장: 한글/영문/숫자/`/`/콤마/언더스코어.
6. 주석 태그 `(E)(N)(F)(O.L)` — 이름 뒤 붙음/한 칸 뒤 모두.
7. `speaker_examples`는 **문서에 실제 존재하는 줄**만, 노이즈(파일명·타임코드·컷번호) 제외.
8. 매치율 기대치 힌트: 화자줄은 보통 전체 줄의 5~60%.
