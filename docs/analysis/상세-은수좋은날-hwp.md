# 은수좋은날 .hwp 대본 포맷 분석

- 대상: `data/대본샘플들/은수좋은날_1회.hwp`, `_7회.hwp`, `_12회.hwp`
- 추출: `pipenv run hwp5txt <file>.hwp` (pyhwp 0.1b15, stderr 없음, 각 파일 1000~1300 라인)
- 표본: 각 화 앞부분 ~200줄 + 중반 ~80줄 (ep1: 1~200, 600~680 / ep7: 1~255, 나머지 스캔 / ep12: 1~150, 그 외 스캔) + 전체 파일에 대한 grep 기반 패턴 통계

## 1. 화자줄 형식: 구분자

**핵심 결론: 화자명과 대사는 구분자 없이 완전히 붙어(glued) 있다.** 콜론(`:`), 탭, 고정폭 공백(3칸 이상) 구분자는 3개 화 전체에서 **단 한 건도** 발견되지 않았다 (`^[가-힣A-Za-z0-9]{1,10}[:：]`, 탭 문자, `이름␣␣␣대사` 패턴 모두 0건).

- ep1 티저의 `은수(N)시작부터 여기까지 정해져 있었을지 모른다.` 는 이 작품의 **보편적 규칙**이며, 예외가 아니다. ep7, ep12의 내레이션(`은수(N)`, `이경(N)`)도 전부 동일하게 붙어 있다.
- 유일한 예외 1건: `ep12.txt:107` `'은수    !!!'` — 화자명 뒤 스페이스 4칸(리터럴 `0x20`×4, 탭 아님) 후 감탄사만 있는 경우. 순수 대사 없이 반응(감탄)만 있는 극히 드문 오타/변칙 사례로 보인다.
- 부가 발견: 문자메시지/채팅 장면(ep1 1045~1225줄, 마약 거래 텔레그램 대화)에서는 별도 서브포맷 `이름_ 메시지내용` (밑줄 + 공백 1칸)을 사용한다. 이는 대사 형식이 아니라 채팅 UI를 흉내낸 표기이며 ep7/ep12에는 등장하지 않는다(ep1에만 국한, 표본 외 다른 화에도 있을 수 있음).

### 실제 예시 15개 (repr)
```
'은수(N)시작부터 여기까지 정해져 있었을지 모른다.'   # 이름+태그(N) 붙음, 서술형 대사
'은수딸, 아직도 안 씻었어?'                          # 이름+대사 완전히 붙음 (구분자 없음)
'진희7분이거든?'                                     # 이름+대사 붙음
'수아(우적우적) 왜? 나 열다섯이야. 이 정도는 쿨하게 들으셔.'  # 이름(행동묘사) + 공백1칸 + 대사
'은수키나 다 크고 말하세요. (콩나물무침을 수아 밥 위에 듬뿍 올리는)'  # 대사 뒤에 괄호(행동) 붙는 변형
'진희(E)야, 박수아!'                                 # 이름+태그(E) 붙음, 오프스크린 대사
'여주(F)왜 이제야 받아. 계속 전화했는데. '            # 이름+태그(F) 붙음, 전화 목소리
'민교(F)아빠-!'                                      # 이름+태그(F) 붙음
'규만(E)억울하지도 않냐?'                             # 이름+태그(E) 붙음
'동현,준현!'                                         # 콤마로 묶인 2인 동시 대사, 붙음
'경도,은수(보는)'                                    # 콤마 다중화자 + 행동(대사 없음)
'학부모1수아 엄마만 투표 안 했어. 찬성이야, 아니야. '  # 숫자 붙은 일반군중 화자
'일동넵! '                                           # 집단 화자
'은수    !!!'                                        # 유일한 예외: 스페이스 4칸 후 감탄사만
'은수(보는)'                                         # 이름(행동)만, 대사 텍스트 없음(리액션 컷)
```

## 2. 화자명 문자 집합

- 대부분 순수 한글 2~3음절 고유명(은수, 도진, 수아, 이경, 태구, 경도, 봉남, 진희, 미연 등).
- **숫자 병기**: 배경/군중 인물은 `기자1`, `학부모1`, `환자1`, `이사2`, `이사3`, `용의자1`, `용의자2` 처럼 "직업/역할명+숫자"로 구분한다. 정규식으로는 화자명 끝에 아라비아 숫자가 붙을 수 있다는 뜻.
- **영문 단독 화자**: 채팅 장면 한정으로 `J_` 처럼 영문 1글자+언더스코어가 화자명으로 쓰인다(위 1번 항목의 서브포맷). 일반 대사 화자명에서 영문 단독 사례는 없었다.
- **집단/복수 화자**: `일동`(다 같이 외침), 콤마로 묶은 다인 동시대사 `동현,준현!`, `경도,은수(보는)`, `이혁,이경모(충격)` — 콤마 사이에 공백 없음.
- `/` 로 화자명을 병기하는 사례는 없음. 단, `성열(남/20대)` 처럼 **지문(서술문) 안에서 인물을 처음 소개할 때** "이름(성별/나이대)" 형태의 캐릭터 소개 주석이 등장하는데, 이건 화자줄이 아니라 지문 문장 중간에 삽입되는 인물 소개이므로 화자 판정 regex의 오탐 후보로 조심해야 함(줄 시작이 아니라 문장 중간에 나타남).

## 3. 주석(괄호 태그) 표기

grep 통계 (3화 합산): `(D)` 152, `(N)` 84, `(E)` 67, `(F)` 16, `(D/N)` 2, `(g)` 2(단위 그램, 오탐 주의)

| 태그 | 의미(추정) | 위치 |
|---|---|---|
| `(D)` / `(N)` / `(D/N)` | Day/Night — **씬 헤더 전용**, 화자줄에는 등장하지 않음 | 씬 헤더 줄 끝 |
| `(E)` | Effect/오프스크린 — 화면 밖 소리·목소리 | (a) 화자명 뒤에 붙어 오프스크린 대사 표시: `규만(E)억울하지도 않냐?` (b) 화자명 없이 줄 자체가 `(E)`로 시작하며 순수 효과음/화면 밖 대사 서술: `(E)콰앙!!!`, `(E)또각 또각 구두소리`, `(E)여기요!` |
| `(F)` | 전화 목소리(필터, Filter) — 전화 통화 상대의 대사 | 화자명 뒤에 붙음: `여주(F)왜 이제야 받아...`, `이혁(F)강휘림한테 들켰다고?` |
| `(N)` (화자 뒤) | 내레이션 — 극중 인물의 독백/보이스오버 | `은수(N)...`, `이경(N)...` 화자명 뒤에 붙어 서술형 대사로 이어짐 |
| `(O.L)` | 오버랩(Overlap) — 이전 대사와 겹치는 대사 | `은수(O.L) 제임스.`, `은수(O.L, 가까이 다가가) 같이 하고 싶어요.` |
| `(행동묘사)` | 순수 지문성 리액션 큐(대사 없이 끝나거나, 대사 앞에 붙음) | `수아(표정)`, `은수(보는)`, `수아(우적우적) 왜?...` |
| `(화면)` | 뉴스/화면 자막 등 특수 낭독 | `앵커(화면)지난달 검거한...` (붙어서 이어짐) |

**공백 유무 패턴(중요, 완전한 규칙은 아님):** `이름(태그)대사` 통계상 공백 없이 바로 이어지는 경우 103건, 공백 1칸 후 이어지는 경우 187건. 경향상 **(N)/(E)/(F)/(화면)처럼 "기술적 태그"는 공백 없이 바로 대사가 이어지는 비율이 높고**, `(도진에게)`, `(우적우적)`, `(불고기를 도진 앞으로 밀며)` 같은 **서술형 행동 지문은 공백 1칸 후 대사가 이어지는 비율이 높다.** 다만 예외도 있어 100% 신뢰 규칙은 아니다.

## 4. 연속 대사(다음 줄로 이어지는 대사)의 형식적 신호

같은 인물의 한 대사가 원본 문서에서 폭(width) 때문에 줄바꿈되면, pyhwp는 그 줄바꿈을 그대로 개행으로 남긴다. 신호:
- 이어지는 줄은 **화자명 접두 없이** 바로 문장 내용(주로 조사/어미로 시작)으로 시작한다.
- 이전 줄과 이어지는 줄 사이에 **빈 줄이 없다** (빈 줄은 "지문 단락 ↔ 대사 블록" 경계에서만 나타나는 편).
- 예:
```
'성열저 반년 됐는데... (조잘조잘) 아 근데 주임님 동네 재개발 '
'확정됐다면서요? 축하드려요. 완전 로또 맞으셨네.'
```
```
'은수(불고기를 도진 앞으로 밀며) 니 아빠 살 빠진 거 안 보여? '
'사람이 꼭 툭 치면 쓰러질 것 같잖니.'
```
- 이어지는 줄이 반드시 미완성 문장인 것은 아니다(위 두 번째 예처럼 첫 줄이 이미 완결된 문장이어도, 같은 화자의 다음 발화가 새 화자 표시 없이 계속되는 "화자줄 없는 후속 대사"도 있음). 즉 규칙은 "새 화자명이 없으면 직전 화자의 대사가 이어진다"에 가깝다.
- 드물게 후속 줄이 리터럴 공백으로 시작하는 경우도 있음(`ep1.txt:307`, `798`, `ep7.txt:534`, `ep12.txt:576` 등 — 원본 정렬/들여쓰기가 그대로 텍스트에 남은 것으로 추정).

## 5. 지문(내레이션/행동 묘사) 줄의 형식

- **들여쓰기 없음.** 지문 줄이 공백/탭으로 시작하는 경우는 극히 드묾(파일당 2~8줄, 대부분은 원본 정렬 artifact이거나 `<제 1 화>` 같은 중앙정렬 타이틀).
- 지문은 3인칭 서술형 문장으로 끝맺는다: `~다.`, `~있다.`, `~보인다.`, `~듯하다.` 류의 종결어미가 압도적. 대사에 쓰이는 구어체 종결(`~요`, `~잖아`, `~거야`)과 뚜렷이 대비된다.
- **화자줄과의 형식적 구별점은 딱 하나: 화자줄은 반드시 알려진 인물명(한글/영문/숫자 조합, 1~8자 내외)으로 시작해 그 인물명이 텍스트에 바로 붙어(또는 태그 붙여) 이어지지만, 지문은 임의의 명사구/부사로 시작할 수 있고 화자명 뒤에 공백 없이 서술이 이어지는 패턴이 나오지 않는다.** 다만 지문 문장이 인물 이름으로 시작하는 경우가 매우 많아(`은수, 얼른 다시 얼굴 숙인다.`, `이경, 어깨 으쓱해 보이고...`) — 이 경우 이름 뒤에 **쉼표**가 오는 것이 핵심 구별 신호다. 화자줄은 이름 뒤 쉼표가 오지 않는다(콤마는 다중 화자 연결에만 쓰임).
- 지문 단락과 대사 블록 사이에는 대체로 빈 줄이 들어간다(빈 줄 비율: ep1 335/1261, ep7 259/1029, ep12 260/1045, 약 25%).
- 지문 중간에 인물 최초 소개 주석이 삽입되는 관행: `성열(남/20대)`, `사장(여/50대)` — 성별/나이대 병기. 씬 헤더/화자줄과 혼동 주의(문장 중간에 등장, 줄 시작이 아님).

## 6. 씬 헤더 형식

- 기본형: `장소[, 세부장소][ - 부가정보] (D|N|D/N)` — 예: `은수 집, 주방 (D)`, `동, 복도 (D)`, `타이틀 시퀀스 (D/N)`, `동현의 원룸 (D) - 과거 (2019년 8월)`, `무인텔 (새벽)`.
  - "동" = 직전 씬과 동일 장소(건물)를 가리키는 관용 표현.
  - 시간 태그는 `D`/`N`/`D/N` 외에 `새벽`처럼 자연어 시간대도 등장(드묾).
  - `- 과거`, `- 현재`, `- 방금 전` 등 하이픈+시제 부가정보가 태그 뒤에 붙기도 함.
- **씬 번호(S#)는 화(episode)마다 있을 수도 없을 수도 있다.**
  - ep1: `0. 프롤로그 (N)` 단 1건만 번호가 있고, 이후 전체 대본에 씬 번호가 전혀 없음(장소명만).
  - ep7: `<제 7 화>` 타이틀 이후부터 `20. 동, 화장실 (D)` 형태로 씬 번호가 시작해 `78.`까지 이어짐(57건). 단, 20~21번은 헤더만 연달아 나오고 본문 내용이 없어(pyhwp 추출 순서 아티팩트이거나 초단문 컷일 가능성) — 신뢰도 낮음.
  - ep12: 씬 번호가 **전혀 없음**(0건), ep1과 동일 스타일.
  - → 씬 번호 유무가 화별로 들쭉날쭉하므로, 씬 헤더 판정 regex는 번호를 optional로 둬야 한다.
- 특수 씬 마커: `인서트> ...`, `플래시백> ...` (`>` 구분자, 종종 `N부#씬번호` 참조 포함: `인서트> 6부 엔딩 이어서`, `플래시백> 7부#18`), `타이틀`/`<제 N 화>`(에피소드 타이틀 카드), `cut to-` (씬 내부 컷 전환, 헤더는 아님), `F.O, F.I`(페이드 아웃/인).
- 종료 마커: `- 1화 끝 -`, `- 12부 끝 -` (하이픈+화수+"끝"+하이픈, 각 화 마지막 줄).

## 7. 화자줄 판정 regex 후보 (Python re)

**2단계 파이프라인을 권장.** 씬 헤더/특수마커를 먼저 걸러낸 뒤 화자줄을 판정해야 오탐이 크게 준다.

```python
import re

# 1단계: 씬 헤더 / 특수 마커 — 이 패턴에 걸리면 화자줄 판정에서 제외
SCENE_HEADER_RE = re.compile(
    r'^(?:\d+\.\s*)?[^()\n,]{1,30}(?:,[^()\n]{1,20})?'
    r'\((?:D|N|E|D/N|N/D|새벽|아침|낮|밤)\)\s*(?:[-–]\s*.*)?$'
)
INSERT_FLASHBACK_RE = re.compile(r'^(인서트|플래시백)>')
END_MARKER_RE = re.compile(r'^-\s*\d+\s*(?:화|부)\s*끝\s*-$')

# 2단계: 화자줄
SPEAKER_LINE_RE = re.compile(
    r'^(?P<name>[가-힣A-Za-z][가-힣A-Za-z0-9]{0,7}'
    r'(?:,[가-힣A-Za-z][가-힣A-Za-z0-9]{0,7}){0,3})'
    r'(?:(?P<tag>\([^()]{1,20}\))(?P<sp>\s?))?'
    r'(?P<dialogue>\S.*)?$'
)

def is_speaker_line(line: str) -> bool:
    s = line.rstrip('\n')
    if not s.strip():
        return False
    if SCENE_HEADER_RE.match(s) or INSERT_FLASHBACK_RE.match(s) or END_MARKER_RE.match(s):
        return False
    m = SPEAKER_LINE_RE.match(s)
    if not m:
        return False
    # 태그 없이 화자명만 있고 뒤에 공백이 있으면(=붙어있지 않으면) 화자줄이 아닐 가능성 높음
    if not m.group('tag') and m.group('dialogue') is None and len(s) > len(m.group('name')):
        return False
    return True
```

- `SCENE_HEADER_RE`가 "이름(태그)" 없이 "장소, 세부 (D)" 형태만 잡도록 콤마·괄호를 제한했지만, 완벽하지 않다.

### 이 regex가 놓치거나 오탐하는 예외 사례
1. **최대 오탐 위험**: `은수 집, 주방 (D)`, `은수 집 앞 (D)` 처럼 **주인공 이름이 장소명 접두어로 쓰이는 씬 헤더**. `SPEAKER_LINE_RE`만 단독 적용하면 이름을 1글자로 백트래킹해 `은` + `수 집, 주방 (D)`처럼 화자줄로 오탐할 수 있음 → 반드시 `SCENE_HEADER_RE`를 먼저 적용해야 함(위 파이프라인에 반영됨). 그래도 `SCENE_HEADER_RE`의 콤마/괄호 제한 조건이 완벽히 씬 헤더만 걸러낸다는 보장은 없어 실제 코드 적용 전 대량 검증 필요.
2. `수아(표정)`, `은수(보는)` 같은 **대사 없는 리액션 큐**는 `dialogue` 그룹이 `None`이 되어 정상적으로 매치되지만, 다운스트림에서 "대사 텍스트"를 기대하는 로직은 빈 문자열을 처리해야 함(대사 추출 시 자동으로 걸러지긴 하나, "화자 등장"으로는 유효).
3. **오프스크린 순수 효과음 줄** `(E)콰앙!!!`, `(E)또각 또각 구두소리`는 화자명이 없어 `SPEAKER_LINE_RE`가 매치하지 않음(name 그룹이 최소 1글자 한글/영문/숫자를 요구하는데 `(`로 시작하기 때문) → 별도로 `^\([^()]{1,10}\)` 패턴을 "화자 없는 오프스크린 대사/효과음"으로 추가 처리해야 함.
4. `기자1`, `학부모1`, `이사2` 등 숫자 붙은 화자명은 `[가-힣A-Za-z0-9]` 클래스에 숫자가 포함돼 있어 매치는 되지만, `어부_`, `J_` 같은 **밑줄 구분 채팅 화자**는 `_`가 클래스에 없어 매치되지 않음(의도적으로 제외 — 채팅 서브포맷은 별도 규칙 필요).
5. `동현,준현!`처럼 **콤마 다중화자**는 매치되지만, 콤마 뒤에 공백이 있는 표기(`동현, 준현!`)가 다른 화에 존재할 가능성은 이번 표본에서 확인 못 함 — 실전에서는 `,\s*` 로 콤마 뒤 공백 허용 권장.
6. `(g)` 같은 단위 표기(`0.5(g)당 40 얼마필요한데?`)가 줄 시작이 아니라 문장 중간에 나오는 경우는 애초에 줄 시작 앵커(`^`)로 인해 오탐하지 않음 — 문제 없음. 다만 화자명이 정확히 1~8자 한글 조합이면서 우연히 실제 인명과 겹치는 지문 문장(`규만이 사회는...`처럼 이름 뒤 조사 "이"가 붙어 자연스럽게 이어지는 지문 문장)은 화자줄과 형식적으로 구별 불가능 — `규만이 사회는 너희한테...`(ep7:11, 지문이 아니라 실제로는 규만의 대사임, `규만` + 조사 없이 바로 이어진 것으로 확인) 등, **화자명 뒤에 조사가 자연스럽게 붙는 경우 지문 문장과 대사 화자줄이 표층 형태로 완전히 동일해질 수 있어 regex만으로는 원천적 한계가 있음.** 이 경우는 인물 명단(화이트리스트) 대조나 문장 종결 스타일(구어체 종결어미) 보조 판정이 필요.

## 8. 빈 줄 / 페이지 머리글 / 특이 라인

- **파일 머리글(문서 제목) 라인**: 각 파일 1번째 줄에 `은수좋은날1회14(241114).hwp`, `은수좋은날7회6(250121).hwp`, `은수좋은날12회12(250206).hwp` 처럼 원본 hwp 파일명 그 자체가 텍스트로 삽입돼 있음(문서 속성/머리글 텍스트박스로 추정). 파일당 정확히 2회 등장하며, **두 번째 등장은 본문 중간 다른 줄 끝에 개행 없이 그대로 붙어버리는 경우가 있다** (예: `ep7.txt:973` `...휘림, 만년필 쥔 손에 힘이 들어간다.은수좋은날7회6(250121).hwp`, `ep12.txt:1044` `- 12부 끝 -은수좋은날12회12(250206).hwp`). hwp 페이지 머리글/바닥글이 본문 텍스트 사이에 삽입 순서 아티팩트로 끼어드는 것으로 보이며, 파싱 전 이 파일명 패턴(`\S+\(\d{6}\)\.hwp` 유사)을 제거하는 전처리가 필요.
- **빈 줄**: 전체의 약 24~26%가 빈 줄. 개행만 있는 순수 빈 줄 외에, 공백 문자만 있는 "위장 빈 줄"도 존재(`ep1.txt:566`, `740`, `1000` 등 `' \n'`) — strip() 후 판정 필요.
- **씬 헤더 줄 끝에 트레일링 스페이스가 다수 붙는 경우**가 있음(`재개발 단지 주택 지붕 (D)                             ` 처럼 헤더 뒤에 공백이 20자 이상 이어지는 줄도 존재) — 표 레이아웃(우측 정렬 셀 등) 흔적으로 추정.
- **`(바스트 추가)`** 같은 촬영/편집 메모가 대사 지문에 섞여 등장(`ep7.txt:787`) — 제작 메모성 삽입, 대사/지문/화자 어느 범주에도 깔끔히 들어가지 않는 노이즈.
- **씬 참조 태그**: 대사/지문 문장 안에 `(6부#27)`, `(5부#36의)`, `(#42)` 처럼 이전 회차/씬 번호를 참조하는 괄호가 자주 섞여 나옴 — 인물 소개 주석 `(남/20대)`과 마찬가지로 화자 태그(`(N)/(E)/(F)`)와 형태는 비슷하지만 문장 중간에 나타나며 내용이 다르므로 줄 시작 앵커(`^`)를 쓰면 자연히 배제됨.
- **`cut to-`**: 씬 헤더가 아니면서 씬 내부 전환을 나타내는 소문자 관용구. 독립된 줄로 등장(`ep12.txt:532`).

## 요약 규칙 (재사용 가이드용)

1. 화자명+대사는 **구분자 없이 붙는다**가 기본 원칙(콜론/탭/다중공백 없음). 예외 1건(스페이스 4칸)만 확인됨 — "일반화 가능"으로 판단.
2. 화자명 뒤 괄호 태그: `(N)`=독백/나레이션, `(E)`=화면 밖 소리·대사, `(F)`=전화 목소리, `(O.L)`=대사 겹침. 화자 없이 `(E)`로 시작하는 줄은 순수 효과음/오프스크린 대사.
3. 씬 헤더는 `장소(,세부) (D|N|D/N|시간대)[- 시제]` 형태이나, **씬 번호(`N.`)는 화마다 있거나 없다** — optional 처리 필수.
4. 최대 리스크는 **화자명이 장소명 접두어와 겹치는 경우**(`은수 집` 등) — 씬 헤더 판정을 화자줄 판정보다 먼저 적용해야 함.
