# xls 대본 샘플 구조 분석: `검은사제들`, `괴물`

대상 파일:
- `data/대본샘플들/KT Studio Genie_검은사제들_대본.xls`
- `data/대본샘플들/KT Studio Genie_괴물_대본.xls`

읽기 방법: `pandas.read_excel(fn, sheet_name=None, header=None)` (엔진 `xlrd`).

공통 사실: 두 파일 모두 시트가 3개(`Sheet1~3` 또는 `Sheet1 - 표 1` 등)이지만 **Sheet2/Sheet3는 완전히 빈 시트**(`shape=(0,0)`)다. `sheet_name=None`으로 순회하는 코드는 빈 시트를 반드시 skip해야 한다. 두 파일 모두 **병합 셀(merged cell)이 0개**임을 `xlrd`의 `sheet.merged_cells`로 직접 확인했다 — 즉 아래에서 설명하는 "값이 여러 행에 걸쳐 쪼개져 들어가 있는" 현상은 셀 병합 때문이 아니라, 워드프로세서 표를 xls로 변환하면서 한 셀의 여러 줄(개행)이 별도의 물리적 행으로 풀려 들어간 것으로 보인다.

---

## 1. 컬럼 구조

**두 파일은 컬럼 구조가 완전히 다르다.** 공통 포맷이 아니라 제작사/각색자마다 다른 "슛리스트 대본" 엑셀 양식을 쓴 것으로 보인다.

### `괴물` — `Sheet1`, `shape=(1630, 5)`, 헤더 행 없음
5개 열 고정폭:

| col | 의미 |
|---|---|
| 0 | 컷 번호 (씬 내에서 1부터 증가) 또는 씬 헤더 텍스트(`S#1 프롤로그 미8군 영안실`), 혹은 `<1권 시작>` 같은 권 구분 마커 |
| 1 | 리터럴 `.` (컷 번호 뒤 구분자). 씬 헤더/마커 행에서는 NaN |
| 2 | **지문(장면 묘사) 텍스트** 또는 **화자명** — 둘 중 하나가 들어간다 (아래 2번 항목 참고) |
| 3 | 리터럴 `:` — 이 행이 "대사 행"인지 아닌지를 가르는 **유일한 스위치**. notna일 때만 col2가 화자명, col4가 대사 |
| 4 | 대사 텍스트 (대사 행일 때만) |

전체 1630행 중 `col3`(`:`)이 채워진 "진짜 대사 행"은 1061행(65%), `col2`만 채워지고 `col3`이 비어 있는 "순수 지문 행"은 402행(25%), 완전 빈 행(씬 구분용)이 75행(4.6%), 씬 헤더 행이 85행이다.

### `검은사제들` — `Sheet1 - 표 1`, `shape=(2009, 16)`, **row2가 실제 헤더 행**
16개 열, 헤더 라벨(row2)은 `S#, 장소, C, 내용, (blank), 대사, (blank×2), (blank), (blank), 비고, (blank), (blank), (blank), 총컷, (blank), (blank)`이며 라벨과 실제 데이터가 있는 열 인덱스는 다음처럼 어긋난다(라벨 셀이 여러 열에 걸쳐 있던 것이 header=None 로 읽으며 좌측 정렬로 깨짐):

| col | 의미 | notna 건수 |
|---|---|---|
| 0 | 씬 번호(S#) — `P1`,`P2`(프롤로그), `O.S`(오프닝 시퀀스 마커), 이후 `1,2,3…` 순증. 새 씬의 첫 행에만 값이 있고 그 외는 NaN | 106 |
| 1 | 장소(로케이션) — 새 씬 첫 행에만, 종종 여러 줄로 쪼개져 다음 몇 행에 걸쳐 분산 입력됨(예: `이탈리아(L)`→`이탈리아`→`성당`→`(O)`가 4개 행에 나뉘어 들어감) | 325 |
| 2 | 컷 번호 — 씬마다 1부터 재시작 | 1725 |
| 3 | 대체로 빈 열(헤더 라벨 `내용`만 존재, 실질 데이터 5건뿐) | 5 |
| 4 | **지문/장면 내용** | 1735 |
| 5,6 | 사실상 빈 열(6은 예외적으로 화자명이 잘못 들어간 6건 존재 — 아래 6번 항목) | 5, 6 |
| **7** | **화자명** (때때로 괄호로 감쌈, 예 `(제자사제)`) | 948 |
| **8** | **대사 텍스트** | 1152 |
| 9 | 헤더 라벨 `비고`만, 실질 0건 | 1 |
| 10 | 사운드/필터 메모(`녹음기 필터`, `전화 필터` 등) — 6건 | 6 |
| 11 | **자막 처리 마커** — 값이 `자막`인 행 89건 + 기타 특수 표기(`전화 필터`,`뉴스 Sound`,`까마귀들` 등) 17건 | 106 |
| 13 | 총컷(스크립트 전체 누적 컷 번호) | 1724 |
| 12,14,15 | 사실상 빈 열 | ≤1 |

`header=None`으로 읽으면 row2("S#","장소","C","내용",…, "총컷")가 데이터의 한 행처럼 섞여 들어온다 — 헤더 스킵 로직이 없으면 이 문자열들이 오분류된다.

**결론: 컬럼 구조는 두 파일이 서로 다르며, 하나의 고정 컬럼 매핑으로 두 파일을 동시에 처리할 수 없다.**

## 2. 화자명이 별도 컬럼인가?

**둘 다 화자명이 별도 컬럼이다.** 대사 셀 자체에는 화자명이 섞여 있지 않다(`화자: 대사` 형태로 셀 내부에 합쳐진 경우 없음).

- `괴물` row15: `[10, '.', '더글라스', ':', "That's right. Let's just dump them in the han river.\n(그래요. 그냥 한강에다 버리라구요.)"]`
  → col2=화자(`더글라스`), col4=대사(영어+`\n`+괄호 안 한국어 번역).

- `검은사제들` row15: `[nan, nan, nan, nan, nan, nan, nan, nan, '인간들이 신을 믿기 때문이지', nan, nan, '자막', nan, nan, nan, nan]`
  → 이 행은 화자 컬럼(col7)이 **비어 있고** 대사(col8)만 있다 — 직전 화자(`스승사제`)의 대사가 다음 행으로 이어지는 "연속 대사" 행이라 화자명이 반복 기입되지 않았다. 실제 화자-대사 짝 예시는 `[..., 7:'제자사제', 8:'그럼.. 그들은 무엇을 하는 겁니까?', ...]` (row10).

## 3. 지문/씬헤더가 행으로 존재하는가?

두 파일 모두 지문과 씬헤더가 **별도의 행**으로 존재하며, 대사 행과 뒤섞이지 않고 컬럼 값 패턴으로 구별 가능하다.

- **`괴물`**: 씬헤더는 `S#1 프롤로그 미8군 영안실`처럼 col0에 텍스트가 있고 col1~4가 모두 NaN인 행. 권 구분(`<1권 시작>`)도 같은 패턴. 지문 행은 `col2`(장면 묘사)가 있지만 `col3`(`:`)이 없는 행 — 예: `20  .  약병을 비우는 김씨 뒷모습  NaN  NaN`. 씬 사이에는 전체 NaN인 구분용 빈 행이 낀다(전체 75건).
- **`검은사제들`**: 씬헤더 정보는 별도 행이 아니라 새 씬의 **첫 데이터 행에 col0(씬번호)/col1(장소)가 채워지는 형태**로 나타난다(예: row3 `P1, 이탈리아(L), 1, 이탈리아 성당 외경`). 지문은 col4에, 대사는 col8에 있고 **같은 행에 지문과 대사가 동시에 존재하는 경우가 888건**이다(예: col4=`스승사제 O.S 제자사제`(지문: 누가 화면 밖에서 말하는지), col8=`그럼 그들은 왜 숨어있는 겁니까?`). 지문만 있고 대사가 없는 순수 지문 행은 847건.

## 4. "셀 하나 = 정제된 대사 한 줄" 가정이 성립하는가?

**부분적으로만 성립하고, 실제로는 여러 지점에서 깨진다.** 현재 코드(`.xlsx`용 `extract_speaker_and_dialogue`)가 가정하는 "셀 = 완성된 대사 한 줄, 그냥 그대로 쓰면 됨"은 이 두 `.xls` 샘플에는 적용할 수 없다.

깨지는 지점:

1. **시트에 대사가 아닌 행이 섞여 있다.** `괴물`은 1630행 중 대사 행이 1061행(65%)뿐, `검은사제들`은 2009행 중 대사 있는 행이 1152행(57%)뿐. 나머지는 지문/씬헤더/빈 행/헤더 라벨 행이다. 시트를 그대로 한 줄씩 밀어넣으면 지문·헤더 텍스트가 "대사"로 오분류된다.
2. **대사 셀이 화자명과 별도 컬럼이라, "셀 하나"만으로는 화자 정보가 없다.** 화자를 붙이려면 다른 컬럼(괴물 col2, 검은사제들 col7)과 조합해야 한다.
3. **대사가 여러 행에 걸쳐 이어지는데 화자명이 첫 행에만 있다** (`검은사제들`에서 화자 없이 대사만 있는 연속 행 205/1152 = 18%). 순수하게 "값 있는 셀만 모으기"를 하면 화자-대사 매핑이 끊긴다(forward-fill 필요).
4. **셀 내부에 이미 2개 언어/2줄이 섞여 있다.** `괴물`의 대사 셀 57/1630행(3.5%, 파일 전체에 산재, 초반부에 국한되지 않음)이 `"영어 대사\n(한국어 번역)"` 형태다. 이런 셀은 그대로 자막으로 쓸 수 없고 한국어 부분만 뽑아내는 후처리가 필요하다.
5. **지문이 대사 셀과 나란히(같은 행, 다른 컬럼) 존재**해서 컬럼을 잘못 짚으면 지문이 대사로 들어간다. `검은사제들`은 같은 행에 지문(col4)+대사(col8)가 동시 존재하는 경우가 888건.
6. **컬럼 위치가 100% 안정적이지 않다.** `검은사제들`에서 화자명이 정규 컬럼(col7)이 아니라 col6에 잘못 들어간 행이 6건 발견됨 — 순수 데이터 입력 오류로 보이나, 고정 컬럼 인덱스만 믿고 파싱하면 이런 행의 화자를 놓친다.
7. **헤더 라벨 행이 데이터처럼 섞여 있다** (`검은사제들` row2: `S#, 장소, C, 내용, …, 총컷`). 스킵 로직이 없으면 헤더 문자열 자체가 대사로 취급될 위험이 있다(다만 이 행은 대사 컬럼(col8)이 비어 있어 대사로 오분류될 가능성은 낮음).
8. **화자명이 괄호로 감싸진 경우가 상당수다** (`검은사제들` 288/948 = 30%, 예 `(제자사제)`). 괄호를 벗기지 않으면 화자 컬럼 값이 지저분해진다. 괄호의 의미(오프스크린/속삭임/단순 표기 관행 차이)는 파일 내에서 일관되지 않아 명확히 규명되지 않음.

## 5. 파이프라인 처리 권고

1. **`.xls`/`.xls(x)` 슛리스트형 대본은 "셀=대사"로 취급하면 안 되고, 컬럼 기반 파서로 전환해야 한다.** 파일마다(제작사/각색자마다) 컬럼 레이아웃이 다르므로 고정 매핑 하나로는 부족하다 — 최소한 "화자 컬럼 인덱스 + 대사 컬럼 인덱스 + (선택)구분자 컬럼"을 파일별로 감지하거나 설정 가능하게 해야 한다.
2. **대사 판별 스위치를 명시적으로 둔다.**
   - `괴물` 류: `구분자 열(":")이 채워진 행만` 대사로 채택. 화자=구분자 왼쪽 열, 대사=오른쪽 열. 콜론이 없는 지문 행/씬헤더 행/빈 행은 제외.
   - `검은사제들` 류: `대사 컬럼(col8 상당)이 non-null인 행만` 대사로 채택. 화자 컬럼(col7 상당)이 비어 있으면 **직전 non-null 화자를 forward-fill**해서 연속 대사를 같은 화자에 붙인다.
3. **화자명 정규화**: 앞뒤 괄호 `(…)` 제거, trim 후 화자로 사용(기존 `SPEAKER_DIALOGUE_REGEX_LIST`의 괄호 지문 제거 로직과 유사한 걸 화자 컬럼에도 적용).
4. **불필요 컬럼(컷번호, 총컷, 비고, 필터 메모, 자막 마커) 제거.** 다만 `자막` 마커 컬럼은 "실제로 화면에 자막으로 노출되는 대사"만 골라내는 선택적 필터로 활용할 여지가 있음(대사의 89/1152=7.7%만 명시적으로 `자막` 태그가 붙어 있어, 태그 없는 대사가 다수이므로 필수 필터로 쓰기엔 근거 약함 — 참고용 정도).
5. **영/한 병기 셀 처리**: `\n(...)` 패턴이 있으면 괄호 안 한국어만 추출(또는 반대로 영어만) 하는 정규식 후처리가 필요. 이 패턴이 붙은 대사가 전체가 아니라 특정 인물(외국인 캐릭터)의 대사에만 산재해 있으므로, 무시하고 그대로 자막에 넣으면 20자 제한 로직도 깨지고 한/영 혼합 줄이 그대로 노출된다.
6. **헤더 행 스킵**: 시트를 읽을 때 "라벨성 문자열 행"(예: 지문/대사/화자 컬럼이 모두 헤더 라벨 텍스트인 행, 또는 대사·지문 컬럼이 전부 비어있고 첫 몇 행에만 나타나는 행)을 컬럼 감지 단계에서 걸러내야 한다. 가장 간단한 방법은 "대사 컬럼이 실제 문장 형태(구두점/조사로 끝남 등)인지" 기존 `extract_speaker_and_dialogue`의 문장 종결어미 휴리스틱을 재사용해 검증 필터로 얹는 것.
7. **빈 시트/빈 행 스킵**: `Sheet2`, `Sheet3`처럼 `shape=(0,0)`인 시트는 순회 시 건너뛰어야 하며, 씬 구분용 완전 공백 행(`괴물` 75건)도 dropna 대상.

## 6. 빈 행 / 병합 셀 / 헤더 행 등 함정

- **빈 행(씬 구분자)**: `괴물`에서 75행, `검은사제들`에서는 완전 공백 행이 5건뿐이지만 대신 "지문만 있고 대사 없는" 행이 847건 있어 별도 필터링이 필요.
- **병합 셀은 없다** (xlrd `merged_cells` 확인 결과 두 파일 모두 0건). 대신 `검은사제들`의 장소(col1) 값처럼 **한 항목의 여러 줄이 물리적으로 별도 행에 쪼개져 들어가는 경우**가 있어(`이탈리아(L)` → `이탈리아` → `성당` → `(O)` 가 4개 행으로 분산), 단순 "값 있는 셀만 훑기"를 하면 문맥이 깨진다. 다만 이 현상은 장소 컬럼에서만 확인되고 화자/대사 컬럼에서는 관찰되지 않았다.
- **헤더 행이 데이터 영역에 섞여 있다**: `검은사제들`은 row2가 실제 컬럼 라벨(`S#,장소,C,내용,대사,비고,총컷`) 행이며 `header=None`으로 읽으면 이 문자열들이 1번째 데이터 행처럼 들어온다. `괴물`은 헤더 행이 아예 없다(순수 데이터부터 시작) — 파일마다 다르므로 "무조건 첫 N행 스킵" 같은 하드코딩은 위험.
- **타입 캐스팅**: `괴물`의 컷 번호(col0)는 판다스가 읽으면 float(예 `1.0`)로 들어올 수 있어, 문자열 결합 시 `.0` 접미사 처리 필요.
- **화자 컬럼 위치가 100% 고정이 아님**: `검은사제들`에서 화자명이 정규 컬럼이 아닌 인접 컬럼(col6)에 잘못 들어간 6건 존재 — 고정 인덱스만 믿는 파서는 이 화자를 놓친다.
- **시트 개수**: 두 파일 모두 물리적으로 시트 3개가 존재하지만 2개는 완전히 빈 시트. `sheet_name=None` 순회 코드가 이를 가정하지 않으면 빈 DataFrame에서 KeyError/IndexError가 날 수 있다.
